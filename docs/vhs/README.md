# Re-recording the demos

Both GIFs in `docs/` are produced by [VHS](https://github.com/charmbracelet/vhs) from the tape
files next to them, so they can be regenerated byte-for-byte rather than re-shot by hand.

```bash
docker build -t mcp-data-profiler-vhs docs/vhs
docker run --rm -v "$PWD:/vhs" mcp-data-profiler-vhs docs/demo.tape
docker run --rm -v "$PWD:/vhs" mcp-data-profiler-vhs docs/mcp-demo.tape
```

On Windows, `${PWD}` in PowerShell. The image mounts the repository at `/vhs` and profiles the
working tree, so a recording always shows the code you have checked out.

| File | What it is |
| --- | --- |
| `Dockerfile` | VHS, ttyd, ffmpeg, JetBrains Mono, and a pinned pandas |
| `prompt.sh` | The shell prompt used on camera |
| `mcp_session.py` | Paces the MCP conversation in `docs/mcp-demo.gif` |
| `../demo.tape` | Hero recording: `python demo.py` |
| `../mcp-demo.tape` | MCP recording |

Everything is pinned — the VHS image by tag, pandas by version — because both recordings show
numbers. pandas 3 reports text columns as `str` where pandas 2 said `object`, and a re-record on
a different version would silently disagree with the profile documented in the README.

## What the MCP recording does and does not stage

The question and the wording of the answer in `mcp_session.py` are scripted; a GIF has to come out
the same every time. Every *figure* is not: the script calls the real `profile_dataset` on a real
file and reads the row counts, sizes, dtypes, statistics, and quality flags back out of the
profile it returns. It cannot show a finding the profiler did not make. Preview the pacing without
recording:

```bash
python docs/vhs/mcp_session.py --speed 2
```

## Two things that will bite you when editing a tape

**Never `Type` a non-ASCII character.** VHS mangles it on the way through ttyd — the characters
vanish, a stray tab triggers filename completion, and the line executes as something else. Every
glyph on screen is written by the program being recorded, never typed by the tape.

**Put a `Sleep` after every command inside a `Hide` block.** VHS types the next line whether or
not the last one has returned. Without the pauses the setup commands are still queued when `Show`
fires, and the recording opens on a screenful of scaffolding.

After re-recording, check the last frame of `docs/demo.gif`: it is the still the README shows most
of the time, and if `Height` is too small for the output the command line scrolls off the top.
